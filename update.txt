GitHub Copilot: npm won't let you republish a version number that already exists, so every update needs a new version.

**To release an update**

1. Edit the code and test it.
2. Commit your changes:
   ```
   git add -A && git commit -m "Describe the change"
   ```
3. Bump the version. Your script `npm run bump` does this, or you can use npm's built-in command:
   ```
   npm version patch
   ```
   - `patch` (1.0.2 → 1.0.3) is for bug fixes.
   - `minor` (1.0.2 → 1.1.0) is for new features.
   - `major` (1.0.2 → 2.0.0) is for breaking changes.

   `npm version` also creates a git commit and tag. If you use `npm run bump` instead, check that it only edits the version number.
4. Publish and push:
   ```
   npm publish --otp=<code>
   git push && git push --tags
   ```

**How people get the update**

- On a NodeBB forum, an admin sees the new version under **Admin → Extend → Plugins** and clicks **Upgrade**. Alternatively, they can run `npm update nodebb-plugin-google-chat-integration` and rebuild.
- The new version shows up in NodeBB's plugin list within a few hours.

**Things to know**

- You can't overwrite a published version. For a bad release, publish a fixed patch version. Within 72 hours of publishing you can also run `npm unpublish nodebb-plugin-google-chat-integration@1.0.2`, but that isn't recommended.
- To flag a broken version, use `npm deprecate nodebb-plugin-google-chat-integration@1.0.2 "Use 1.0.3"`.
- If you change the settings storage format, keep a migration for old data, as `loadSettings` already does for the single-webhook format.
